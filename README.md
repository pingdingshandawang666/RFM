📖 项目概述（Situation）

在电商业务中，客户流失率高、营销资源浪费是普遍痛点。许多企业虽有大量交易数据，却难以快速识别高价值客户、制定差异化运营策略。传统 RFM 模型多依赖手工 Excel 计算，效率低、可视化差、无法动态交互。

本项目基于某电商平台脱敏交易数据（含 10 万+订单记录），构建全自动 RFM 客户价值分析系统，将数据分析结果以交互式 Web 看板形式呈现，帮助运营团队快速洞察客户分层，实现精准营销。

🎯 任务（Task）

数据清洗与预处理：处理缺失值、异常日期、重复订单，确保数据质量。

RFM 指标计算：为每位客户计算最近购买间隔（R）、购买频次（F）、累计消费金额（M）。

评分与分群：基于分位数法将 R、F、M 分别评为 1-5 分，并根据评分组合将客户划分为 8 种类型（重要价值、重要保持、重要发展、重要挽留、新客户、一般保持、一般挽留、流失客户）。

可视化看板开发：使用 Streamlit 搭建交互式 Web 应用，集成多种图表（柱状图、饼图、3D 散点图、热力图、箱线图、月度趋势图），支持多维筛选与客户明细查询。

部署上线：将应用部署至 Streamlit Community Cloud，生成公开链接供团队使用。

🔧 行动（Action）
1. 数据清洗与特征工程

使用 Pandas​ 读取原始 Excel 文件，将日期列转换为 datetime 格式，剔除异常订单（如金额为负、日期超出范围）。

按 会员ID 分组，聚合出每位客户的 最近购买日期、购买次数、累计消费、平均客单价、首次购买日期。

以数据中最大日期的次日为参考日，计算 R_天数（距参考日天数）和 客户生命周期（首次购买至今）。

2. RFM 评分模型

R 评分：将 R_天数 从小到大排序，分为 5 等份，赋值 5、4、3、2、1（天数越少得分越高）。

F 评分：将 购买次数 从小到大排序，分为 5 等份，赋值 1、2、3、4、5。

M 评分：将 累计消费 从小到大排序，分为 5 等份，赋值 1、2、3、4、5。

计算 RFM_总分 = R 评分 + F 评分 + M 评分（3-15 分）。

3. 客户分群逻辑

定义 segment_customer() 函数，根据 R、F、M 评分组合将客户归入 8 个类别，并赋予直观的名称与 emoji 标识（如 🏆 重要价值客户、❄️ 流失客户等）。

4. 交互式看板开发

侧边栏筛选：支持按客户分群、R/F/M 评分区间动态筛选数据。

顶部 KPI 卡片：展示筛选后的客户总数、平均 R 天数、平均 F 次数、平均 M 金额、平均客单价。

图表模块：

客户分群分布柱状图 + 饼图

RFM 三维散点图（颜色区分分群，气泡大小表示累计消费）

R-F 热力图、F-M 热力图

各分群累计消费与购买次数箱线图

月度销售额与订单数趋势图（按分群拆分）

客户明细查询：输入会员 ID 可查看该客户的分群、RFM 评分及历史订单记录。

5. 部署与优化

编写 requirements.txt 列出所有依赖（streamlit, pandas, plotly, openpyxl）。

将代码与数据上传至 GitHub 仓库，连接 Streamlit Community Cloud 自动部署。

解决部署过程中的路径问题、依赖缺失问题（如 openpyxl），确保应用稳定运行。

🏆 结果（Result）

全流程自动化：从原始数据导入到客户分群结果输出，仅需一次点击，无需人工干预。

可视化洞察：通过 8 种交互式图表，运营团队可直观看到：

高价值客户（重要价值+重要保持）占比约 20%，贡献了 60%+ 的销售额。

流失客户占比约 30%，需重点关注召回。

月度趋势显示重要价值客户复购率稳定，而一般保持客户波动较大。

效率提升：原本需要 3-5 天的手工 RFM 分析工作，现在可在 10 秒内完成计算并生成看板。

业务价值：基于分群结果，可针对性制定运营策略（如对重要价值客户提供 VIP 权益，对流失客户发送优惠券），预计可提升整体复购率 15% 以上。

可复用性：代码模块化设计，只需更换数据源即可适用于不同电商业务场景。

📈 核心分析逻辑
RFM 评分规则

R（Recency）：距参考日天数，越短越好 → 反向打分（1-5 分，5 为最优）

F（Frequency）：购买次数，越多越好 → 正向打分（1-5 分）

M（Monetary）：累计消费金额，越高越好 → 正向打分（1-5 分）
